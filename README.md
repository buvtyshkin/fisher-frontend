# Fisher Frontend

Персональный фронтенд для длинных литературных ролевых игр с Claude через
прямой Anthropic API. Техзадание — в `SPEC.md`, правила работы — в `CLAUDE.md`.

## Стек

- **Сервер:** Node.js + TypeScript + Fastify
- **База:** SQLite (`better-sqlite3`), один файл в `data/fisher.db`
- **Интерфейс:** React + Vite, тёмная тема
- **Порт:** 8787 (SillyTavern на 8000 не трогаем)
- **Node:** v24 через nvm (см. `.nvmrc`). Системный `/usr/bin/node` остаётся v20 —
  SillyTavern запускается именно им и обновления не замечает.

## Запуск

```bash
nvm use                 # версия из .nvmrc
npm install
cp .env.example .env    # и вписать ANTHROPIC_API_KEY
npm run dev             # сервер :8787 + интерфейс :5173
```

Если Node не той версии, любая из команд `dev`, `build`, `start`, `test`
остановится с понятным сообщением, а не с ошибкой про `NODE_MODULE_VERSION`.

Открыть http://localhost:5173

Боевой режим (один процесс, отдаёт и API, и интерфейс):

```bash
npm run build
npm start               # http://localhost:8787
```

## Дерево чата

Чат — дерево, а не список. У каждого сообщения есть родитель; ветки, свайпы и
правки — это одно и то же: альтернативные дети одного родителя. Ничего не
перезаписывается и не удаляется.

- **Свайп** — ещё один вариант ответа рядом со старым.
- **Править** — новая версия становится соседом, прежний текст остаётся в дереве.
- **Ветвиться** — вернуться к старому сообщению и продолжить историю иначе.
- **‹ 2/3 ›** — переключение между вариантами; ветка разворачивается до своего
  собственного конца, а не обрывается на развилке.
- **Продолжить** — дописывает оборванный ответ в то же сообщение, без нового узла.
  Токены и стоимость суммируются с уже потраченными на этот ответ.

Счётчик «веток: N» в шапке показывает, сколько у чата концов.

## Деньги

Цены лежат в `pricing.json` — доллары за миллион токенов по каждому типу
(вход, выход, запись в кэш, чтение из кэша). Файл читается заново при каждом
изменении, перезапуск сервера не нужен.

**Стоимость ответа считается один раз, в момент генерации, и хранится в базе.**
Правка `pricing.json` влияет только на новые ответы — история расходов не
переписывается. Ответы, созданные до появления этого поля, были оценены
однократно при миграции по действовавшему тогда прайсу.

Модель, которой в файле нет, сохраняет токены, но остаётся без стоимости, и
панель расходов называет её отдельной строкой. Если позже добавить ей цену,
такие ответы будут оценены при следующем запуске — терять там нечего.

Токены расширенного мышления API возвращает внутри `output_tokens`, поэтому
отдельной строки для них нет: они уже посчитаны как выход.

Кнопка «Расходы» в шапке показывает суммы за сегодня, за последние 24 часа и
за последние 7 дней с разбивкой по типам токенов.

## Разметка сообщений

Поддерживается небольшое подмножество markdown, достаточное для прозы:
`*курсив*`, `**жирный**`, `_курсив_`, `__жирный__`, цитаты через `>`,
заголовки `#`, `##`, `###` и горизонтальная линия `---`.
Разбор — в `web/src/markdown.ts`, отображение строится из React-элементов,
поэтому текст модели не может превратиться в разметку страницы.

## Структура

```
server/        API и работа с базой
  config.ts      настройки из .env
  db.ts          схема SQLite
  store.ts       чтение/запись чатов и дерева сообщений
  provider.ts    адаптер Anthropic (интерфейс ProviderAdapter)
  pricing.ts     расчёт стоимости по pricing.json
  routes/        HTTP-маршруты
scripts/       проверка версии Node перед запуском
pricing.json   цены за миллион токенов — правится руками
web/           интерфейс (React)
test/          тесты
data/          база (в git не попадает)
```
