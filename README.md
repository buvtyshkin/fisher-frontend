# Fisher Frontend

Персональный фронтенд для длинных литературных ролевых игр с Claude через
прямой Anthropic API. Техзадание — в `SPEC.md`, правила работы — в `CLAUDE.md`,
состояние работ и накопленные выводы — в `HANDOFF.md`.

## Стек

- **Сервер:** Node.js + TypeScript + Fastify
- **База:** SQLite (`better-sqlite3`), один файл в `data/fisher.db`
- **Интерфейс:** React + Vite, тёмная тема
- **Порт:** 8787 (SillyTavern на 8000 не трогаем)
- **Node:** v24 через nvm (см. `.nvmrc`). Системный `/usr/bin/node` остаётся v20 —
  SillyTavern запускается именно им и обновления не замечает.

## Запуск

```bash
nvm use                 # версия из .nvmrc
npm install
cp .env.example .env    # и вписать ANTHROPIC_API_KEY
npm run dev             # сервер :8787 + интерфейс :5173
```

Если Node не той версии, любая из команд `dev`, `build`, `start`, `test`
остановится с понятным сообщением, а не с ошибкой про `NODE_MODULE_VERSION`.

Открыть http://localhost:5173

Боевой режим (один процесс, отдаёт и API, и интерфейс):

```bash
npm run build
npm start               # http://localhost:8787
```

## Перенос чатов из SillyTavern

Кнопка «Импорт» в списке чатов принимает файл `.jsonl` из
`SillyTavern/data/default-user/chats/<персонаж>/`.

- Каждая реплика становится узлом дерева; свайпы (`swipes` + `swipe_id`) —
  соседями одного родителя, активным остаётся тот, что был активен в ST.
  Неиспользованные свайпы превращаются в отдельные концы веток и никуда
  не пропадают.
- `is_system` в SillyTavern означает «остаётся в чате, но не уходит в промпт» —
  так там прячут суммаризованную историю. Флаг переносится: без него чат на
  700 реплик отправил бы в API всё разом. Такие сообщения показываются
  приглушёнными с пометкой «не уходит в запрос»; вернуть или скрыть любое
  сообщение можно кнопкой под ним.
- Если карточка с именем из названия файла уже импортирована, она привязывается
  к чату автоматически.

## Плагины

Серверные модули в папке `plugins/`, загружаются при старте. Плагин — это файл,
экспортирующий по умолчанию объект с именем и любыми из трёх хуков:

- `beforePromptBuild(context)` — перед отправкой запроса; может переписать
  `system` и `messages`;
- `afterResponse(context)` — после сохранения ответа, асинхронный: сюда встанут
  хронисты и аудиторы;
- `onMessageRender(message)` — преобразует сообщение по пути в интерфейс.

Плюс `action` — кнопка в шапке чата и модальное окно с её результатом.

Упавший хук пишется в лог и пропускается: плагин не может уронить генерацию.
В комплекте `plugins/example-stats.ts` — пример со всеми тремя хуками и
кнопкой «Статистика», он же документация.

## Хроники

Сжатые пересказы прошедших сцен — кнопка «Хроники» в шапке. Уровни: сцена,
арка, глава.

Хроника привязана к узлу дерева: якорем становится **последнее покрытое ею
сообщение**. Она видна ровно тем веткам, что через этот узел проходят. Хроника
о событиях одной ветки не попадёт в соседнюю; хроника о времени до развилки
видна обеим — это общее прошлое.

- Текст пишется вручную или запрашивается у модели по промпту из
  `chronicle-prompt.md` (файл правится руками, перезапуск не нужен).
  Сгенерированный текст сначала попадает в редактор — сохраняется только после
  вашей правки.
- Хроника старшего уровня собирается из младших: если внутри выбранного
  диапазона уже есть хроники ниже уровнем, модель получает их, а не сырые
  сообщения.
- Флаг «скрыть суммаризованные сообщения» убирает покрытый диапазон **из
  запроса к API**. В дереве и на экране сообщения остаются. Если диапазон
  относится к другой ветке, скрывать здесь нечего — и не скрывается.
- В промпт хроники попадают блоком `chronicle` (он же макрос `{{summary}}`),
  в порядке следования по ветке, с пометкой уровня и названия.

Стоимость генерации хроник учитывается в панели «Расходы».

## Кэширование

Точки кэширования (`cache_control`) ставятся так же, как в SillyTavern
(`cachingAtDepthForClaude`): глубина считается **сменами ролей** от конца,
хвостовые реплики ассистента пропускаются, ставятся **две** точки — на
`CACHE_DEPTH` и на `CACHE_DEPTH + 2`. Пара «катится»: глубокая живёт несколько
ходов, ближняя подхватывает свежий текст. Системный промпт кэшируется отдельным
префиксом. TTL — час по умолчанию (`5m` доступен настройкой).

Сверх ST выполняется инвариант из ТЗ: **ничего сдвигающегося не остаётся внутри
кэшируемого префикса**. Инъекция на глубину (блок пресета с
`injection_position: 1`, `depth_prompt` карточки, лорбук на глубине) едет по
списку сообщений с каждым ходом; окажись точка кэширования после неё, префикс
ломался бы на каждом запросе и кэш не читался бы никогда. Точка отодвигается
вглубь, а сдвиг не делается молча — он пишется в предупреждения экрана «Промпт»
с именем виновной инъекции.

### Прогрев при простое

Пока никто не пишет, кэш продлевается сам: чтение кэша сбрасывает его таймер
бесплатно, поэтому раз в `CACHE_REFRESH_MINUTES` (по умолчанию 50, при часовом
TTL) отправляется тот же запрос с `max_tokens: 0` — модель прогоняет префикс,
ничего не генерирует и не тарифицирует выход. Стоимость такого запроса — одно
чтение префикса.

Прогревочный запрос собирается **тем же сборщиком**, что и боевой: префикс,
отличающийся хотя бы байтом, оплатился бы как новая запись по двойной цене
вместо чтения. Если ответ приходит без `cache_read`, в лог пишется
предупреждение — значит, префикс всё-таки разошёлся.

Прогреваются только последние `CACHE_REFRESH_CHATS` чатов (по умолчанию один) и
только пока их касались не дольше `CACHE_REFRESH_IDLE_HOURS` назад: каждый
прогрев стоит денег, и держать тёплой всю библиотеку смысла нет.

Расходы на прогрев учитываются в панели «Расходы» — они входят в общую сумму и
показаны отдельной строкой.

Настройки — в `.env`: `CACHE_DEPTH` (`-1` выключает точки в сообщениях),
`CACHE_SYSTEM`, `CACHE_TTL` (по умолчанию `1h`), `CACHE_REFRESH`,
`CACHE_REFRESH_MINUTES`, `CACHE_REFRESH_CHATS`, `CACHE_REFRESH_IDLE_HOURS`. Экран «Промпт» показывает, где стоят точки и
сколько это от конца; строка под каждым ответом — сколько токенов ушло в запись
кэша и сколько прочитано, и во сколько обошёлся ответ.

## Лорбуки

World Info из SillyTavern импортируется в библиотеке и экспортируется обратно
теми же байтами. К чату можно подключить несколько лорбуков сразу.

Активация повторяет `public/scripts/world-info.js` из SillyTavern 1.18:

- `constant` — всегда; иначе совпадение по основным ключам в последних
  `WI_SCAN_DEPTH` сообщениях (запись может задать свою глубину);
- ключ вида `/шаблон/флаги` — регулярное выражение, оно отменяет остальные
  настройки сопоставления;
- вторичные ключи по `selectiveLogic`: AND ANY, NOT ALL, NOT ANY, AND ALL;
- рекурсия: сработавшая запись может активировать другую. `preventRecursion` —
  содержимое записи не запускает других, `excludeRecursion` — запись не
  активируется на рекурсивном проходе;
- `probability` учитывается;
- сообщения в буфере сканирования разделены управляющим символом, поэтому ключ
  не может совпасть через границу сообщений — как в ST.

Вставка: `position` 0 — до карточки, 1 — после, 4 — в историю на `depth` с
ролью записи. Записи сортируются по `order` по убыванию и вставляются в начало,
что даёт итоговый текст **по возрастанию `order`**, склейку через `\n` — так же,
как это делает ST. Позиции 2, 3, 5, 6 (заметка автора и примеры) пока не имеют
слота; такие записи не теряются молча, а попадают в предупреждения.

Глобальные настройки — в `.env` (`WI_SCAN_DEPTH`, `WI_RECURSIVE`,
`WI_CASE_SENSITIVE`, `WI_MATCH_WHOLE_WORDS`), значения по умолчанию совпадают с
настройками ST этой установки.

**Про «целые слова»:** в SillyTavern границу слова задаёт `\W`, а в JavaScript
`\w` — только латиница. Поэтому для кириллических ключей эта настройка не
работает ни там, ни здесь: «кот» сработает внутри «котлеты». Воспроизведено
намеренно, чтобы срабатывания совпадали.

Чего пока нет: бюджет токенов на World Info (`world_info_budget`),
минимальные активации, групповое взвешивание, `sticky`/`cooldown`/`delay`,
имена в буфере сканирования.

Движок сканирования — за интерфейсом `LorebookEngine`, чтобы позже подставить
умный ретривер.

## Сборщик промпта

Пресеты SillyTavern (Chat Completion, JSON) импортируются в библиотеке.
Воспроизводится семантика сборки ST:

- порядок блоков из `prompt_order` для нужного персонажа, выключенные пропускаются;
- блоки-маркеры (`charDescription`, `charPersonality`, `scenario`,
  `personaDescription`, `dialogueExamples`, `chatHistory`) наполняются из
  карточки, персоны и ветки чата;
- `injection_position: 1` — абсолютная инъекция в историю на `injection_depth`
  (0 — после последнего сообщения), несколько на одной глубине идут по
  `injection_order` по возрастанию;
- `extensions.depth_prompt` карточки инъектируется тем же механизмом — так же,
  как это делает ST;
- соседние блоки одной роли склеиваются; ведущие system-блоки становятся
  параметром `system`, а system-блок после начала диалога — ходом пользователя
  (`system` внутри списка сообщений API не принимает).

Чат без пресета работает на встроенном пресете-заглушке — это не отдельная
ветка кода, а обычный пресет, поэтому движок сборки всегда один.

**Макросы**: `{{user}}`, `{{char}}`, `{{group}}`, `{{description}}`,
`{{personality}}`, `{{scenario}}`, `{{persona}}`, `{{mesExamplesRaw}}`,
`{{summary}}`, `{{setvar::x::y}}`, `{{getvar::x}}`, `{{trim}}`,
`{{// комментарий}}`. Неизвестный макрос даёт пустую строку и предупреждение —
упасть из-за макроса нельзя.

**Кнопка «Промпт»** в шапке показывает собранный запрос: по блокам (с ролью,
идентификатором и глубиной инъекции) или сплошным текстом для посимвольной
сверки с дампом ST. Там же — предупреждения и список включённых блоков,
которые вышли пустыми.

Чего пока нет и что видно в отладке: `{{summary}}` (Фаза 6),
префиксы имён (`names_behavior`). Параметры сэмплинга из пресета читаются и
показываются, но не отправляются — текущие модели Claude их отклоняют;
`max_tokens` из пресета используется.

## Персонажи и персоны

Кнопка с именем персонажа в шапке открывает библиотеку.

- **Импорт карточек**: PNG с встроенной карточкой (блок `chara` или `ccv3`;
  при наличии обоих берётся V3) и чистый JSON. Поддерживаются V1, V2 и V3 —
  поля не переизобретаются, объект `data` хранится как пришёл.
- **Экспорт**: карточка возвращается в формате SillyTavern — PNG со встроенным
  блоком (`ccv3` для V3, иначе `chara`) или JSON, если PNG не было.
- **Приветствия**: при привязке карточки к пустому чату `first_mes` становится
  первым сообщением, а `alternate_greetings` — свайпами рядом с ним.
- **Редактор**: поля карточки правятся на месте. Поля, которых нет в форме
  (включая `extensions` с настройками из ST), переносятся без изменений.
  После правки экспорт PNG пересобирается с новой карточкой — само изображение
  остаётся прежним байт в байт.
- **Персоны** заводятся вручную: имя и описание, оба попадают в промпт.

`{{char}}` и `{{user}}` в приветствиях и в промпте уже подставляются. Полный
набор макросов и порядок блоков придут вместе с пресетами в Фазе 3 — сейчас
системный промпт собирается простой склейкой полей карточки и персоны
(`server/prompt.ts`).

## Дерево чата

Чат — дерево, а не список. У каждого сообщения есть родитель; ветки, свайпы и
правки — это одно и то же: альтернативные дети одного родителя. Ничего не
перезаписывается и не удаляется.

- **Править своё сообщение** — главный способ ветвления, как на Claude.ai.
  Новая редакция становится соседней веткой, и модель сразу отвечает на неё.
  Прежняя линия целиком доступна через `‹ n/m ›` на вашем сообщении.
- **Свайп** — ещё один вариант ответа рядом со старым.
- **Править ответ модели** — правка её слов. Ответ не перегенерируется:
  это исправление, а не новая попытка.
- **Продолжить** — дописывает оборванный ответ в то же сообщение, без нового
  узла. Токены и стоимость суммируются с уже потраченными на этот ответ.
- **Сгенерировать** — кнопка внизу. Появляется, когда ход за моделью: последнее
  сообщение ваше или это ещё не сдвинувшееся приветствие карточки.

Инвариант: ни одно действие не оставляет чат в состоянии, из которого не видно,
как получить ответ. Если ход за моделью — кнопка «Сгенерировать» на виду.
Проверяется тестом, а не на глаз.

Счётчик «веток: N» в шапке показывает, сколько у чата концов.

Всё дерево целиком можно посмотреть прямо из базы, минуя интерфейс:

```bash
npm run tree                  # список чатов
npm run tree -- <id|название> # дерево: ● текущая ветка, ○ сохранённые
```

## Деньги

Цены лежат в `pricing.json` — доллары за миллион токенов по каждому типу
(вход, выход, запись в кэш, чтение из кэша). Файл читается заново при каждом
изменении, перезапуск сервера не нужен.

**Стоимость ответа считается один раз, в момент генерации, и хранится в базе.**
Правка `pricing.json` влияет только на новые ответы — история расходов не
переписывается. Ответы, созданные до появления этого поля, были оценены
однократно при миграции по действовавшему тогда прайсу.

Модель, которой в файле нет, сохраняет токены, но остаётся без стоимости, и
панель расходов называет её отдельной строкой. Если позже добавить ей цену,
такие ответы будут оценены при следующем запуске — терять там нечего.

Токены расширенного мышления API возвращает внутри `output_tokens`, поэтому
отдельной строки для них нет: они уже посчитаны как выход.

Кнопка «Расходы» в шапке показывает суммы за сегодня, за последние 24 часа и
за последние 7 дней с разбивкой по типам токенов.

## Разметка сообщений

Поддерживается небольшое подмножество markdown, достаточное для прозы:
`*курсив*`, `**жирный**`, `_курсив_`, `__жирный__`, цитаты через `>`,
заголовки `#`, `##`, `###` и горизонтальная линия `---`.
Разбор — в `web/src/markdown.ts`, отображение строится из React-элементов,
поэтому текст модели не может превратиться в разметку страницы.
