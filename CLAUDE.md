Fisher Frontend — правила проекта
Что это
Персональный фронтенд для длинных литературных ролевых игр с Claude через прямой Anthropic API. Замена SillyTavern для одного пользователя. Не универсальный комбайн: один пользователь, один основной провайдер (Anthropic), один жанр (длинная проза на русском языке).
Полное техзадание и план работ — в файле `SPEC.md`. Читай его перед началом работы. Текущий статус фаз отмечай прямо в SPEC.md (чекбоксы).
Общение
Пользователь — опытный пользователь SillyTavern и prompt-инженер, но НЕ программист. Объясняй решения простым языком, без снисходительности.
Общение — на русском. Код, комментарии в коде, имена переменных — на английском.
Перед крупными архитектурными решениями, не описанными в SPEC.md, — сначала спроси, предложив 2–3 варианта с коротким обоснованием.
Правки по замечаниям — точечные: исправляй то, что назвали, не переписывай всё вокруг.
Незыблемые принципы
Совместимость с форматами SillyTavern — закон. Карточки персонажей (Character Card V2/V3, PNG со встроенным JSON), лорбуки (World Info JSON), пресеты (Chat Completion preset JSON), чаты (JSONL) должны импортироваться. Экспорт обратно в форматы ST — тоже обязателен для карточек и лорбуков. Мы не изобретаем свои форматы там, где есть форматы ST.
Чат — это дерево, а не список. Каждое сообщение знает своего родителя (parent_id). Ветки, свайпы и правки сообщений — это одна и та же механика: альтернативные дети одного родителя. Никаких копий файлов чата.
Кэш — гражданин первого класса. Сборщик промпта обязан выдавать стабильный префикс: всё волатильное (заметки, инъекции малой глубины, динамика) — строго ПОСЛЕ точки кэширования. Точки кэширования (cache_control breakpoints) — явная настройка, не магия. Эквивалент cachingAtDepth из ST должен поддерживаться.
Субтрактивный подход. Не добавляй функции, которых нет в SPEC.md. Если чего-то не хватает — предложи, но не делай молча. Меньше кода — меньше поломок.
Расширяемость через хуки, а не через правки ядра. Три точки: beforePromptBuild, afterResponse, onMessageRender. Будущие модули (Plot Director, хронист, аудитор, генерация изображений) встают в эти гнёзда.
Стек
Node.js (актуальный LTS) + TypeScript. Бэкенд: Fastify или Express — на твой выбор, обоснуй.
База: SQLite (через better-sqlite3 или аналог). Один файл, простой бэкап.
Фронтенд: простой веб-интерфейс. Без тяжёлых фреймворков ради фреймворков; React допустим, если ускоряет работу. Тёмная тема по умолчанию.
Деплой: Ubuntu VPS (Hetzner), systemd-сервис, доступ через Tailscale. Порт не должен конфликтовать с SillyTavern (она на 8000).
Секреты (API-ключи) — в .env, никогда в коде и никогда в git.
Дисциплина
Работай малыми шагами: одна фаза SPEC.md → рабочий результат → пользователь проверяет руками → следующая фаза.
После каждой фазы: краткая инструкция пользователю, как проверить результат (какие команды выполнить, что открыть в браузере, что должно получиться).
Тесты — на критичные места: сборка промпта, парсинг макросов, импорт форматов ST, работа с деревом сообщений. UI-тесты не нужны.
git: коммить после каждого завершённого шага с понятным сообщением.
