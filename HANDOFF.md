## Решения, которые стоит помнить

**Один движок сборки.** Чат без пресета работает на встроенном пресете-заглушке,
а не по отдельной ветке кода. Импорт пресета ST просто заменяет его.

**Стоимость фиксируется в момент генерации** (`messages.cost_usd`). Правка
`pricing.json` влияет только на новые ответы, история не переписывается.

**Ветвление сделано по образцу Claude.ai:** правка своего сообщения = новая
ветка плюс немедленный ответ. Отдельной кнопки «ветвиться» нет. Инвариант
«из любого состояния виден способ получить ответ» закреплён тестом.

**Continue — не prefill.** Текущие модели Claude отклоняют запрос,
заканчивающийся репликой ассистента, поэтому «продолжить» и «сгенерировать
после приветствия» добавляют служебный ход пользователя. Константы —
в `server/routes/chats.ts`.

**Параметры сэмплинга из пресета не отправляются** — модели их отклоняют.
Значения видны в отладочном экране отдельной строкой.

**Прогрев кэша идёт через тот же сборщик**, что и боевой запрос: префикс,
разошедшийся на байт, оплатился бы как новая запись по двойной цене.

## Совместимость с SillyTavern: что выяснено из её исходников

ST установлена на этом же сервере. Код — `/root/SillyTavern/public/scripts/`
и `/root/SillyTavern/src/`, данные — `/root/SillyTavern/data/default-user/`.
**Семантику сверять с ними, а не по памяти** — трижды она оказалась
противоположной ожидаемой:

1. **Порядок лорбука.** `sortFn = (a,b) => b.order - a.order` плюс `unshift`
   даёт итоговый текст по **возрастанию** `order`, склейка через `\n`.
2. **Флаги рекурсии.** `excludeRecursion` запрещает активацию **на**
   рекурсивном проходе; `preventRecursion` — содержимое записи не запускает
   другие. Не наоборот.
3. **`cachingAtDepth`** считает глубину **сменами ролей**, пропускает хвостовые
   реплики ассистента и ставит **две** точки: на `depth` и на `depth + 2`.

Реальные данные тоже опровергали предположения:

- **У всех карточек есть `extensions.depth_prompt`** — ST инъектирует его
  в чат на глубину. Без этого сверка расходится на каждой карточке.
- **`is_system` стоит на ~96% сообщений** в длинных чатах и означает
  «остаётся в чате, но не уходит в промпт» (`chat.filter(x => !x.is_system)`).
  Так спрятана суммаризованная история. При импорте флаг переносится
  в `messages.hidden_from_prompt`.
- **Настройки World Info пользователя**: `world_info_recursive: true`,
  `world_info_match_whole_words: true`, глубина 2. Умолчания приведены к ним.

**Сознательное расхождение с «правильным» поведением:** проверка целого слова
в ST строится на `\W`, а в JavaScript `\w` — только латиница, поэтому для
кириллических ключей настройка не работает («кот» срабатывает внутри
«котлеты»). Воспроизведено намеренно и закреплено тестом, чтобы срабатывания
совпадали с ST. Если понадобится правильное поведение — это отдельный флаг.

## Чего сознательно нет

- systemd-сервис (отложен пользователем).
- Бюджет токенов на World Info (`world_info_budget`), минимальные активации,
  групповое взвешивание, `sticky`/`cooldown`/`delay`, имена в буфере
  сканирования.
- Префиксы имён (`names_behavior`) в сборщике промпта.
- Позиции лорбука 2/3/5/6 (заметка автора, примеры) — такие записи не теряются
  молча, а попадают в предупреждения.
- Карта дерева в интерфейсе — отложена; вместо неё `npm run tree` и
  переключатель `‹ n/m ›` у развилок.
- Групповые чаты, другие провайдеры, TTS, генерация изображений — вне ТЗ.
