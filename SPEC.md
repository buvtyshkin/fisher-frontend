Fisher Frontend — техзадание
1. Цель
Личный веб-фронтенд для ролевых игр и совместного письма с Claude (Anthropic API), заточенный под длинную литературную прозу. Заменяет SillyTavern для одного пользователя, сохраняя совместимость с её форматами данных, чтобы миграция была обратимой.
Что строим: чаты с полноценным ветвлением, персонажи и персоны, сборщик промпта с поддержкой пресетов ST, лорбуки, хроники (аналог STMemoryBooks), система плагинов.
Что НЕ строим: групповые чаты, поддержку десятков провайдеров, TTS, встроенную генерацию изображений (позже — плагином), мобильное приложение (достаточно адаптивной вёрстки), многопользовательский режим.
2. Сущности (модель данных)
Chat — контейнер: название, привязанный персонаж, персона, пресет, лорбуки, указатель на активный лист дерева (active_leaf_id).
Message — узел дерева: id, chat_id, parent_id (null у корня), role (user/assistant/system), content, created_at, метаданные (модель, токены, стоимость). Ветка = путь от корня до листа. Свайп = ещё один ребёнок того же родителя. Правка сообщения = новый узел-сиблинг (старый остаётся в дереве).
Character — карточка в формате Character Card V2/V3. Хранится как импортированный JSON + оригинальный PNG. Поля не переизобретаем — используем спецификацию V2/V3.
Persona — имя, описание, аватар.
Preset — импортированный Chat Completion preset из ST (JSON): список prompt-блоков с их порядком, позициями и глубинами инъекции, параметры сэмплинга, max_tokens и т.д.
Lorebook — импортированный World Info (JSON): записи с ключами, вторичными ключами, позицией вставки, порядком, глубиной сканирования, флагом рекурсии.
Chronicle — запись хроники уровня scene/arc/chapter: текст-суммарий, привязка к узлу дерева (anchor_message_id) и к диапазону узлов, который она покрывает. Хроника видна ветке, если её якорь лежит на пути от корня до текущего листа.
Settings — глобальные: API-ключи (в .env), настройки кэширования, тема, размеры.
3. Сборщик промпта (ядро системы)
Вход: активный пресет + карточка + персона + лорбуки + хроники + ветка чата.
Выход: массив messages для Anthropic Messages API + system + точки cache_control.
Требования:
Воспроизвести семантику сборки ST: порядок блоков из prompt_order, injection_position (0 = относительный порядок, 1 = абсолютная инъекция в чат на глубину injection_depth), injection_order, роли блоков, склейка соседних system-сообщений (squash).
Макросы — поддерживаемое подмножество: `{{user}}`, `{{char}}`, `{{group}}`, `{{setvar::x::y}}`, `{{getvar::x}}`, `{{trim}}`, `{{// комментарий}}`, `{{mesExamplesRaw}}`, `{{summary}}`, `{{scenario}}`, `{{personality}}`, `{{persona}}`, `{{description}}`. Неизвестный макрос: подставить пустую строку, записать предупреждение в лог. Ничего не должно падать из-за неизвестного макроса.
Кэширование: настройка «глубина точки кэширования» (эквивалент cachingAtDepth: 2 из ST) + extended TTL (1h) как опция. Инвариант: всё, что меняется каждый ход, попадает в промпт ПОСЛЕ последней точки кэширования. Отладочный экран: показать собранный промпт целиком с отметками, где стоят breakpoints и что закэшировано.
Anthropic API: нативный адаптер (messages, system, streaming опционально, extended thinking с настраиваемым бюджетом). Интерфейс адаптера — абстрактный (ProviderAdapter), чтобы позже добавить OpenAI-совместимый для других провайдеров, но сейчас реализуем только Anthropic.
4. Лорбуки
Импорт/экспорт World Info JSON как есть.
Активация записей: сканирование последних N сообщений по ключам (учёт регистра по флагу), вторичные ключи (AND/NOT-логика ST), рекурсивное срабатывание (запись активирует запись), constant-записи.
Вставка в промпт согласно позиции записи (before/after char, at depth) и order.
Интерфейс движка (LorebookEngine) — подменяемый: позже сюда встанет умный ретривер на дешёвой модели.
5. Хроники (аналог STMemoryBooks)
Ручной режим (MVP): пользователь выделяет диапазон сообщений → «создать хронику» → текст пишется вручную или запрашивается у модели по настраиваемому промпту → сохраняется с якорем.
Уровни: Scene → Arc → Chapter. Хроники старших уровней собираются из младших.
Инъекция в промпт: отдельным блоком (позиция настраивается в пресете через блок `{{summary}}` или собственный слот), только хроники, чей якорь лежит на текущей ветке.
Опция «скрыть суммаризованные сообщения из контекста» (сообщения остаются в дереве и UI, но не уходят в API).
6. Интерфейс
Список чатов, окно чата, панель персонажей/персон, редактор лорбуков, редактор пресетов (минимальный: включение/выключение блоков, правка содержимого, порядок), настройки.
Дерево: навигация по веткам (переключатель веток у сообщения с сиблингами, «карта дерева» — простая схема со счётчиком веток), кнопка «ветвиться отсюда», свайпы (генерация альтернатив), правка любого сообщения, «продолжить» (continue с обрыва).
Русский язык интерфейса. Тёмная тема. Адаптивная вёрстка для телефона (доступ через Tailscale с s24-ultra).
Отображение: markdown, курсив/жирный, цитаты; счётчик токенов контекста и стоимости ответа.
7. Плагины
Серверные модули (TS/JS) в папке plugins/, загружаются при старте.
Хуки: `beforePromptBuild(context)` — может мутировать собранный промпт; `afterResponse(context, response)` — асинхронный, для хронистов/аудиторов; `onMessageRender(message)` — для UI-обвесов.
Слоты UI: кнопка в панели инструментов чата + модальное окно (минимум для MVP).
Пример-заглушка плагина в комплекте (как документация).
8. Импорт из SillyTavern
Чаты: импорт JSONL → линейная цепочка узлов дерева. Свайпы из ST-формата — сиблинги.
Карточки: PNG V2/V3 и чистый JSON.
Лорбуки: World Info JSON.
Пресеты: Chat Completion preset JSON (см. раздел 3).
Персоны: из ST-настроек, вручную допустимо (их мало).
9. Фазы работ
[x] Фаза 0 — скелет. Сервер + SQLite + минимальный UI: один линейный чат с Anthropic API (ключ из .env), сообщения сохраняются. Критерий: можно поговорить с Claude через свой интерфейс.
[x] Фаза 1 — дерево. parent_id, ветвление, свайпы, правка сообщений, навигация по веткам, continue. Критерий: создать ветку из середины чата, переключиться между ветками, ничего не потерять.
[ ] Фаза 2 — персонажи и персоны. Импорт PNG-карточек V2/V3, привязка к чату, персоны. Критерий: импортировать реальную карточку из ST, начать с ней чат.
[x] Фаза 3 — сборщик промпта. Импорт пресета ST, движок блоков + макросы, отладочный экран промпта. Критерий: импортировать Modular Core v2, собранный промпт посимвольно сверить с тем, что собирает ST (отладочный дамп).
[x] Фаза 4 — лорбуки. Импорт World Info, активация, вставка. Критерий: рабочий лорбук из Fisher Universe срабатывает на те же триггеры, что в ST.
[ ] Фаза 5 — кэширование. Breakpoints, глубина, extended TTL, отображение cache hit/miss и стоимости. Критерий: на длинном чате второй запрос подряд показывает cache read, а не полную стоимость.
[ ] Фаза 6 — хроники. Сущность Chronicle, ручное создание, генерация по промпту, инъекция с учётом ветки, скрытие суммаризованного. Критерий: хроника из одной ветки не протекает в параллельную.
[ ] Фаза 7 — плагины и миграция. Три хука, пример плагина, импорт JSONL-чатов из ST. Критерий: перенести один реальный длинный чат из ST и продолжить его здесь.
Порядок фаз менять нельзя без обсуждения: каждая опирается на предыдущую.
10. Критерий готовности MVP
Полный игровой цикл Fisher Universe без обращения к SillyTavern: импортированная карточка + пресет + лорбук, длинный чат с ветвлением, работающий кэш, хроники. SillyTavern остаётся на VPS нетронутой как запасной вариант.
